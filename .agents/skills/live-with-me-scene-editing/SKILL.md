# 场景与相机调整

区分资产几何、摆放变换与观看相机。用户要物件变大时调整完整对象；用户要视野变近时调整相机，不通过移动丘陵、改草地或缩放单个子组件代偿。

## 整体缩放与移动

- 建筑以 `src/world/scene/sceneLayout.ts` 为默认布局，包含位置与当前比例；保留用户存档的庭院偏移，不把存档状态当成源码默认值。院中花草、南瓜架、蜂箱等有独立布局，不因附近建筑缩放而跟着放大。
- 用 `npm run scene:geometry -- scale --entity capsule_pod --percent=-5` 计算建议；指定物件不在支持列表时明确给出位置、比例和局部接地点。工具只输出，应用前核对输入来自仓库默认还是用户实际保存位置。
- 固定局部接地点 `a`，当前位置 `p`、比例 `s` 变为 `s'` 时，位置为 `p'=p+a*(s-s')`。不要把已补偿的新位置再次当作历史 `scaleAtGround` 的原始位置；它按原始比例 1 计算，重复补偿会漂移。
- 同一完整组应带动视觉、人物、接触影、点击区和房间锚点；主屋等锁定对象是否可移动以用户当前授权为准，别为了工具计算解锁。
- 变换之后查看实体包络 `explorationBounds.ts`、房间目标 `roomTargets.ts` 和庭院深度，只有本次改变确实影响它们时才修改。

## 地面方向与坐标

地面点沿现有 `.285` 纵向压缩旋转，复用 `src/world/scene/placementMath.ts` 的 `rotateGroundPoint`。柱、树干、草叶等先旋转脚点，再加竖直高度；不直接对完整立面使用屏幕旋转或剪切。

`sceneTypes.ts` 区分 local、scene、viewBox、client；`entityPointToScene` 将局部点带入建筑布局，`cameraMath.ts` 处理场景与 viewBox，交互拖动用实际 `getScreenCTM().inverse()` 换算。不要将屏幕像素当成物件局部坐标；同一拖动在不同倍率下应按相机矩阵换算。

## 相机取景

- `roomTargets.ts` 管房间目标、局部锚点和上下文范围；`overviewFraming.ts` 管整屋构图；`cameraBounds.ts`／`useWorldCamera.ts` 管平移缩放约束。按触发问题修改相应职责，避免扩大一处取景改动。
- “13 寸屏幕”不是确定的 CSS 视口。优先读取当前实际 viewport，或明确使用的宽高；根据用户指定的可见顶部／底部目标检查投影位置，不凭硬件对角线猜缩放。
- 缩放倍率接近全景时尤其检查上下、左右是否过早锁死；用实际可探索实体包络判断边界，不为露出主丘去移动丘陵。环境视差、麦田和远山保持原状态，除非用户明确授权修改。
- SVG `getBBox` 会包含可能不应计入相机的装饰／动画范围，别直接将整组 bbox 替代已有实体包络。临时截图取景也不能写回正式相机或用户布局。

## 检查与交付

用 `npm run check:target -- --area camera` 查看候选；仅在涉及对应逻辑时执行选中的单测与视角用例。用 `--e2e --grep` 缩小浏览器范围，不自动扩展到跨浏览器矩阵。整体缩放先核对固定接地点，再看实际场景比例和边界；并说明默认布局与浏览器保存状态的差别。
