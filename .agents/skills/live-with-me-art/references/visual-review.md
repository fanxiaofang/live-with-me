# 轻量视觉检查

只检查本次变化能影响的内容。实际场景尺寸用于判断主次与密度，近景用于检查结构；近景更精细不代表场景中更协调。

## 一次合并复核

先明确本轮改变了什么、要解决什么可见问题。默认先看正常场景里的摆放、比例、遮挡与必要命中，再对具体交接看局部；多个对象尽量共用一次浏览器会话。可靠的当前截图可以提供判断依据；旧版截图只作参照，不能证明新修改已生效。

静态资产重点判断：品种和主要形体是否可辨、主体色块是否完整、与邻物的明暗主次是否合适、根点／支点／枝梗连接是否成立。植物变体还看成组重复感与密度；地面还看无作物时是否贴地。按本轮风险选相关项，不把它们扩展成每轮全量清单。

用户已明确检查范围或要求不检查时遵循其范围，交付如实说明限制。语法检查只说明可解析，不是类型检查或视觉验收；不要用反复语法检查替代实际画面判断。

## 选择检查

- 小幅图形或改色：当前场景与相关局部即可，不为静态形状编写镜像实现的单测。
- 主题逻辑或颜色适配变化时检查受影响主题；沿用既有主题逻辑的小幅静态改色，不默认扩展到全套日／暮／夜截图。
- 有人物、摆动、拖动等相关变化：检查对应状态，确认接地点、遮挡、命中区和必要的保存行为。
- 涉及共享资源：核对使用者，只在获准图层切换；需要时用 DOM 标记确认近处变体没有进入丘陵层。
- 修改 TS 类型、接口或接入代码时按风险选择对应类型检查；新增物件复用既有庭院能力，核对注册、挂载与一条代表性交互／保存链路即可，不按每件重复验证全部拖动、历史和存档。改变交互或保存实现时再扩大相关检查。
- 工具可用或文档列有某项检查不构成必跑理由；范围明确后不额外列计划。纯文档变动只复核文字、引用与范围，不启动应用或测试。

## 使用截图助手

需要额外截图时，可在项目根目录运行（使用项目已安装的 Playwright 与 Edge，不安装新依赖）；这是可选取景工具，不是每轮前置步骤：

```powershell
node .agents/skills/live-with-me-art/scripts/preview-asset.mjs --selector '#guardian-heritage-tree' --out test-results/art-review/osmanthus
```

颜色改动确有需要时添加 `--themes '白天,夜晚'`；默认使用当前主题。可设 `--url http://127.0.0.1:3000/`、`--width 1440`、`--height 1000`、`--timeout 60000`。主题按钮不存在时应使用相应页面自己的控制，不扩展生产 UI。

每个状态输出 `scene-*.png`、`detail-*.png` 与 `review.json`。目标选择器必须唯一且有可见面积；助手等待目标与相机稳定，以完整目标居中取近景并再次检查取景位置，不修改生产文件或布局存档。主题切换与近景取景只发生在独立浏览器上下文中。

这只是截图助手，不是视觉验收测试。查看生成的实际图像，检查目标是否被别的对象遮挡、关键交接是否完整以及颜色／细节密度是否合适。只看到截图路径、DOM 数量或成功退出不算检查完成。

## 防止重复返工

先确认预览服务已加载新组件或新路径，避免截图旧画面。优先复用正常场景取景；必要的临时取景在截图后还原，不写回正式相机。目标不存在、取景不稳定或被裁切时先定位原因，不原样反复重试，不将错误截图当成果。

截图与定向检查足以覆盖当前改动后结束；只有新改动、失败或具体疑点才重复相关检查。交付写明实际检查和限制，不把“生成图片”写成用户已经认可美术风格。
