## 2. 本专项目标

取得当前版本可重复、可比较的基线，并用局部对照定位主要成本，为资产工作台、新桌子和生态屋顶提供成本参照。先按证据选择局部处理；React＋SVG、局部缓存或混合渲染的取舍在测量后决定。

## 3. 测量方法与诊断范围

1. 核对当前工作区/构建，记录代码状态、设备、浏览器、视口、DPR、主题、人物及预览开闭状态。保留用户的开发服务和未提交成果。
2. 使用正常动画的生产版本，以可用前台浏览器为主要体验证据，现有无头脚本为补充。可用桌面环境覆盖 DPR 1/2；内置浏览器和真实手机的结论分别记录，窄屏模拟不能代替真实手机。
3. 固定输入，重复至少三轮：全景静止、房间静止、拖动、滚轮缩放、房间切换；午后和静雨优先，深夜及首次详细查看按具体风险补测。
4. 保存 P50/P95、最大帧间隔、卡顿事件及长任务，并用短时性能记录区分脚本、样式、绘制、栅格化和合成。长任务少也不代表画面流畅。
5. 只对疑似热点做诊断对照，例如背景滤镜、部分动画或重复更新；一次改变一个主要因素。记录 trace/录制自身开销，用相同操作轻量复验。
6. 如果证据支持修正，局部实施后同条件复测。若原因未清楚，缩小场景或进一步分组；不能提前指定删除细节或更换渲染器。

`stableScene` 可用于固定截图和功能检查，不能用于正常动画性能结论。60Hz 的 16.7ms 是参考帧预算，验收目标应结合实际设备与基线确定。

### 6.4 脚本、绘制、栅格化与合成的证据边界

静止段 React 根提交通常为 0；短 trace 的 FunctionCall 耗时远低于持续绘制和 GPU 进程任务。平移约 32 次根提交、滚轮约 12 次、房间切换 1–2 次，输入有脚本工作，但不能解释零提交静止时持续出现的长帧。长任务少不等于流畅。

trace 同时取得 CrRendererMain 的 UpdateLayoutTree / Layout / Paint、RasterTask 工作线程、Compositor 事件及 CrGpuMain 的 GPUTask。GPU 进程任务时间包含 CPU 提交、驱动和等待，RasterTask 是工作线程 CPU 时间；都不是纯 GPU shader 时间，也不能跨线程相加为墙钟占比。事件可嵌套，汇总保留 inclusive 标签。

## 7. 诊断后的工程决定（2026-10-15）

**当前保留 React + SVG；优先改进持续动画和镜头缩放的渲染方式。现有证据不足以支持全场更换技术栈，也不足以保证继续叠加动态环境后仍可接受。** 本节是依据第 6 节结果作出的决策，尚未实施运行时优化。

### 7.1 测试结果对技术选择的意义

- 静止段通常没有 React 根提交，却仍有长帧；暂停全部 CSS 动画后，有窗口 DPR 1 全景/阁楼 P95 从约 67ms 接近同环境空白页的约 34ms。持续成本主要指向动画驱动的样式、SVG 绘制及后续管线。仅拆 React 组件或增加 memo 不足以解决这类成本；React 继续负责界面、状态、布局与交互。
- 缩放的长帧伴随明显栅格化工作，滚轮也有主线程长任务。需要检查镜头变换、绘制失效范围与静态内容复用，不能只优化提交次数，也不能断言脚本完全无关。
- 家具、人物和可交互细节继续使用 SVG，保留矢量清晰度与现有资产。尚未锁定某一个云雾、植物或滤镜为唯一瓶颈；分层、缓存或混合绘制都需实际场景对照，增加绘图库不会自动解决问题。
- Canvas/WebGL 只作为特定环境层的后备候选：先完成局部优化实验，若收益不足且证据指向该层，再做独立比较。比较必须包括清晰度、内存、命中交互、裁切/遮挡、更新失效和维护成本；本次不批准全面迁移。

### 7.2 增加 SVG 资产和环境渲染的成本判断

| 后续内容 | 成本与当前决定 |
| --- | --- |
| 少量静态家具 SVG | 可以继续小样。主要增加挂载、首次绘制及平移/缩放或失效后的重绘成本；路径复杂度、遮挡和滤镜面积会影响结果。静态不等于零成本，不能凭节点数承诺容量 |
| 校准工具与多方向素材预览 | 按需挂载，关闭后卸载调试内容；分别比较开/关成本。生产只消费选定几何、接触点和当前姿态 |
| 植被摇摆、烟雾、灯光等持续动画 | 可能持续触发样式、绘制及合成，是当前优先约束项；先验证局部更新，逐组加入并测增量 |
| 大面积雨雪、雾、模糊、透明叠层和动态屋顶植物 | 高风险，成本可能随覆盖面积、DPR、层间依赖及镜头变化增加，不能简单按资产数量线性估计。先验证环境层渲染方案，再扩大效果；第三阶段仍未启动 |
| 静态屋顶粗样 | 可按原计划审阅体量和镜头；细节、植物动画、剖面和遮雨裁切分别计成本，不能把粗样通过当作完整环境效果通过 |

目前没有测得“还能增加多少资产”的安全上限，也没有真实手机或内置浏览器的性能结论。暂停动画的对照仅证明优化方向，不能作为删除已认可软影、人物细节或取消正常动画的交付方案。

4. **给直接的开发决定并结束。** 输出一张简表：“具体动画 → 已确认影响/尚未确认 → 替代方式 → 是否保留”，随后回到场景制作。简单修正有效就保留；没有有效办法则记录局部风险和适用边界，不自动扩成渲染重构。范围更大的方案另行判断。
