# 房间导航与取景优化

2026-10-09。顺序：先测量并处理房间切换延迟，再调整各房间取景，最后回归验证。用户要求本轮结束后停下，不直接进入第三阶段。

## 问题与改动

旧房间切换先更新 activeRoom，再由被动 effect 更新 camera，两次提交之间仍显示旧相机。activeRoom 传入整套建筑组件，少量选中多边形变化会重建大量 SVG；App 的内联家具选择回调、每次新建的 LayoutGestureContext 值也影响缓存。

当前 focus 相机在选择提交时直接派生，layout effect 同步手势引用；手动漫游状态继续独立保存。RoomSelectionContext 只驱动房间高亮叶节点，原资产绘制顺序与轮廓不变。稳定家具选择回调、编辑手势 provider 值后，房间导航不会连带重建整套建筑。四个相机层共用 cameraMotion 的 400ms 过渡；地形覆盖保留到 450ms，快速操作会重新计时；拖动与减少动态效果偏好继续取消过渡。

最终拖动检查定位到背景资产仍重复创建未变的麦田、云带和拖拉机 JSX。RollingWheatSilhouette 使用 memo，云带与拖拉机子树按实际依赖缓存；需要变化的地形裙边继续随覆盖参数更新，梯度引用与悬浮交互不变。主舞台使用常驻 will-change 提示。相同全景拖动场景共 14 次提交，最终平均 React 渲染为 11.29ms，最大 17.50ms；上一轮已确认的地形版本平均为 14.05ms。两轮记录见 [最终拖动](metrics/ROOM_NAVIGATION-pan-final.json) 和 [上一轮地形拖动](metrics/LANDSCAPE-render-result.json)，仍是开发版本机单次测量。

原三个主屋房间 zoom=1.55，且所有焦点从旧平移参数反推。新主屋 zoom 为 1.18–1.20，前廊为 1.08；胶囊、小木屋、电波站保留适合小设施的 1.40–1.55。localAnchor 改为实际活动/设施中心，contextSize 在局部空间描述取景范围；按可见 slice 宽高与实体 scale 下调缩放，避免手机沿用桌面裁切。前廊焦点略低于画面中心，给屋内连接关系留出空间。cameraBounds 同时允许手机较低 zoom 的房间 focus 及周边拖动。

overview 保留 `{x:0,y:135,zoom:0.66}`。本轮没有移动建筑、拖拉机或南瓜架，没有扩展天气、昼夜、生态粒子效果。

窄屏检查还暴露出顶部栏覆盖同住面板收起按钮、房间名称被挤成竖排的问题。PresencePanel 在 sm 以下下移；底部导航在 sm 以下限制宽度、横向滚动、保留完整房间名，并避开布局校准器按钮。桌面位置与排版保持原样，导航用 aria-current 表达选中状态。

## 真实页面测量

`tests/fixtures/app-profile.html` 包装真实 App，使用 React 开发版 Profiler；`tests/e2e/room-switch-profile.spec.ts` 通过原生导航点击记录点击、DOM 相机目标、RAF 首次检测到变换、transitionend 与 React 提交。环境为 Windows、Chromium 141、DPR 1、1200×800；每轮按相同八处导航顺序进行。下表前后两轮都启用了默认 Playwright trace 录制，它会给大型 SVG 检查增加开销。

| 八次切换平均 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 点击到相机目标提交 | 318.93ms | 40.20ms |
| React 累计渲染耗时 | 243.22ms | 30.12ms |
| RAF 首次检测到变换 | 888.76ms | 744.91ms |
| 点击到过渡结束 | 1490.64ms | 992.41ms |

原始记录：[修改前](metrics/ROOM_SWITCH-before.json)、[只改渲染和过渡](metrics/ROOM_SWITCH-motion.json)、[取景调整后](metrics/ROOM_SWITCH-after.json)。修改前每次两次提交；修改后多数一次，首次切入有一次极小的地形覆盖收敛提交。数据随本机负载变化，是单轮本地实验，不代表真实设备的 FPS 或性能保证。

最终静态背景缓存之前，另一次 [关闭 trace 的测量](metrics/ROOM_SWITCH-untraced.json) 为：平均目标提交 66.45ms、React 累计渲染 52.23ms、首次检测到变换 712.06ms、过渡结束 1025.42ms。关闭录制后第一帧仍有开销，不能把所有延迟归因于 trace；这轮不是最终代码，也不能与录制开启的修改前记录直接作同比。

诊断页面中分别临时暂停微动画、添加四层 will-change 提示、关闭 SVG 滤镜进行了对照。SVG 绘制仍有明显开销，单独添加合成提示没有稳定解决第一帧延迟。生产代码没有采用这些全局诊断开关，也没有宣称第一帧达到 400ms 或 60fps。更广泛的滤镜与 SVG 合成优化留待用户后续决定第三阶段范围。

## 验证

响应式取景、房间焦点随 placement 变化、相机边界、坐标与存储共 27 项单元测试通过。浏览器检查覆盖快速切换、选择与相机同次提交、四层相同过渡时间、减少动态效果偏好、resize 后的聚焦与拖动，以及三个屏幕尺寸下七处房间主体的可见性。

完整编辑遍历继续检查 35 件家具的选择、微调和保存，以及 136 次原生把手拖动、键盘微调、运行错误与相机保持不变。默认 trace 录制逐步捕获整个巨大 SVG，初次遍历因总时限退出，已有坐标断言并未失败。layout-editor.spec.ts 关闭 trace，继续保留失败截图和所有断言；35 件遍历总预算调整为 120s，136 次拖动维持 360s。重跑两项全部通过，分别约 58.8s 和 5.7 分钟。其余输入、地形、交互、生命周期、人物与错误恢复检查通过；原键盘测试的 1.55 取景断言同步更新为 1.20。

三个视口共 21 张房间截图已逐张检查：1200×800、1600×900、390×844。七处房间焦点均保留活动主体及周围关系。整栋小屋、深夜、静雨、空席四张已确认基线保留原文件，只有七处新房间取景更新基线。最终代码的 11 项视觉对比全部通过，四张已确认全景基线的 SHA-256 与上一轮一致。

本轮 53 项非视觉浏览器测试分批回归通过。最终背景缓存改动后，相关的 29 项检查再次全部通过（11 项视觉对比、11 项地形连续性、5 项房间导航、1 项键盘交互、1 项导航与编辑保存），约 8.3 分钟。最终 `npm run lint`、27 项单元测试及生产打包通过；构建仍有既有主包超过 500kB 的提示。

最终生产包在 4173 端口通过 7 项预览检查（导航与编辑保存、键盘交互、5 项房间导航），约 1.5 分钟。生产环境的快速切换、四层过渡、减少动态效果偏好、三种尺寸取景、resize 与再次聚焦均通过。诊断用的 React DevTools 分支探针已删除，保留真实 App 的测试专用 Profiler fixture 及原始记录。

## 后续视觉简化

2026-10-09，按用户要求取消房间内部的选中区域虚线与填色，以及胶囊、林间小木屋和电波站的选中圆圈及光晕。室内地板改为固定透明点击区域，保留点击与键盘导航；移除不再使用的 RoomSelectionContext 与 ActiveRoomOnly。底部导航仍表达选中房间，相机参数及过渡保持本轮已确认值。上述性能记录对应取消装饰之前的版本，未为这项纯视觉简化重复测量性能；第三阶段仍未启动。

该简化通过类型检查、生产构建及 7 项相关画面/交互检查。五处受影响截图全部重新生成并逐张查看，确认没有区域虚线与选中光圈；整栋小屋、深夜、静雨、空席四张全景基线的 SHA-256 保持一致。测试临时复用已运行的本地服务，临时配置已清理。
