## 1. 结论与依据

建议先修正人物与家具的静态空间关系，建立当前生产场景的性能基线，再进入天空、天气与昼夜光效。猫狗的活动方向和草地材质规则应提前设计，完整散步、喝茶、翻身动画及全部环境细节不作为第三阶段的强制前置条件。

理由是人物比例、坐姿接触、椅子结构、麦田轮廓属于几何问题；昼夜配色与大气属于环境问题。几何不稳定时先增加光照和动作容易重复调整。性能测量必须前移且贯穿各批次，集中优化仍可保留在第三阶段。

本次读取了用户引用的 ChatGPT 对话“调研Anatomy等距SVG能力”。接口提供了用户关于投影、Zdog、人物席位、椅子、海报、麦田/山丘和胶囊的消息；助手回复返回引用占位符，无法核实其完整论证。工具能力以下游项目官方说明及当前本地代码为依据，未直接沿用该对话中不可读的助手结论。

检查范围包括当前阶段规划、`DESIGN.md`、人物席位配置、人物与家具绘制入口、猫狗组件、地形与磨损组件、历史性能记录，以及实际浏览器的当前全景。**本次没有重新测量 FPS、生产绘制耗时或移动设备性能。**

## 3. 人物和动物：按使用位置制作姿态

### 3.1 八个使用位置不等于八个朝向

2026-10-13 调查时，`src/features/presence/presenceAllocation.ts` 定义八个席位：书桌、茶几三席、懒人沙发、胶囊床、木屋床和电波站。后续桌椅修订已增加第二桌席，不能继续把“八席”当成当前固定容量；新布局中的固定工作位置与临时站台需要分别处理。当前朝向标签与姿态不是同一个概念；`characterFacing.ts` 提供四个朝向标签，但仅增加枚举不能生成正确的身体。

先为每个实际使用位置建立静态样例，分别记录姿态、面向、接触点和绘制层级。坐姿以臀部/坐面为主要锚点，站立与行走以脚底为锚点，睡姿以头枕/被沿为锚点。脸朝向改变不能替代肩、躯干、手臂、腿和衣服的重画。

首个试点建议选书桌椅：空椅 → 就坐人物 → 接入桌子 → 更换不同装扮验证。茶几西席可以共享东席的部分几何，但配饰、手部与桌子的关系要单独验收；不能只把整体镜像就视为完成。两张床可共享人物特征，但必须适应各自床铺的局部投影。

先核对后方家具、人物远侧肢体、躯干、近侧肢体和前方桌沿/靠背的局部顺序。全景检查可辨认性，房间近景检查自然性，独立预览用于检查结构，不能仅在放大的单体图上验收。

### 3.2 猫狗需要姿态，但无需一次画完全部组合

当前 `NyankoSenseiCat.tsx` 与 `ShibaInuPuppy.tsx` 主要提供固定窝垫中的蜷睡/伏卧造型和点击反馈，没有 `pose`、`facing` 的活动形态接口。猫窝/狗窝与动物身体应在活动功能实施时分离，窝保持家具身份，动物身体可换姿态和位置。

建议首轮形态为：猫的蜷睡与站立、狗的伏卧与站立，再按固定散步路线补实际可见的侧面、前斜面、后斜面。若路线确实需要八方向再补齐；方向标签不意味着八张图必须同时挂载。不同姿态保留猫的斑纹、项圈和体型，狗的黄白分布、耳朵和尾巴，不用匿名轮廓替代原来的动物。

随后再制作少量可循环的步态：外层位移沿路线行走，内层腿、尾和身体做局部动作。动画帧数与频率根据视觉效果和测量决定，不先承诺统一帧数。静止/睡觉占主要时间，散步偶发出现，符合低打扰陪伴目标。

路线实施需明确室内/室外范围、避开家具和台阶的区域，以及在桌腿、栏杆、建筑前后穿行的层级。场景镜头当前只有缩放和平移，**拖动镜头不会产生新的观察方向**；动物需要换方向主要来自它自己的转身和活动。

隐藏标签页、不可见动物与减少动态效果偏好应有暂停或静态状态。位置和动作不要通过每帧更新 App 的人物/全局状态驱动整座小屋重渲染；只挂载当前形态，预计算方向资产。

### 3.3 工具与当前投影

[Anatomy 官方说明](https://github.com/wheresryan22/anatomy#limits) 明确把机械、仪器、工具、家具作为适用对象，不把人物作为其擅长范围。可优先试用于椅子结构、柜体或胶囊局部圆弧几何，人物/猫狗仍需要独立的造型与接触关系设计。其静态 SVG 输出可作为制作流程中的资产，不必在网页中常驻其 3D 运行时。

[Anatomy 的相机实现](https://github.com/wheresryan22/anatomy/blob/main/kit/iso-kit.mjs) 支持 azimuth / elevation 参数，默认分别为 45° / 30°。项目主屋视觉地面轴约为 ±15.806°（斜率 ±0.283088），这是屏幕上地面线相对水平线的角度，**不是相机方位角或俯仰角**。不能把工具的 elevation 直接设成 15.806°就认定匹配；还需检查竖向尺度、比例、局部家具投影和现有手绘资产。以已确认场景为参照做一个家具样例，不统一改造所有旧投影或布局 Gizmo。

[Zdog API](https://zzz.dog/api) 有分组、旋转和 SVG 渲染能力，可以试做人物/动物的体块与多方向制作工具。但自然造型、衣服、正确坐姿和家具遮挡仍需自己设计。建议先验证一个模型的风格和投影，再把选定方向烘焙为静态 SVG/JSX；只有实际动作需要时才考虑运行时使用。官方 [Canvas / SVG 说明](https://zzz.dog/extras#canvas-or-svg) 也指出大量独立 SVG 元素的渲染和排序可能影响性能，不能把换库当成性能保证。

本次未安装 Anatomy、Zdog 或其他新依赖。若后续正式采用工具或复制其代码，仍需按具体固定版本核对许可、依赖和输入边界。

## 4. 性能：先取得能比较的基线

2026-10-15 延续：已有生产样本及长帧证据继续保留，当前要补主要成本定位及同条件比较，详细方法与新增结果统一维护在 [性能专项](SCENE_PERFORMANCE_DIAGNOSIS.md)。以下保留原始评估背景和测量原则，不表示本次已重新采样。

历史 `P7-render-result.json` 的固定 pan 为 React 开发 Profiler 平均 2.2ms；后续 `ROOM_NAVIGATION-pan-final.json` 为 11.29ms。两者来自不同代码节点/测量时刻，不是同一轮生产浏览器绘制对照。`ROOM_SWITCH-untraced.json` 曾记录约 183–383ms 的最大帧间隔；相关说明明确指出它在最终静态背景缓存之前，不能当成当前版本测量。

这些记录证明项目曾有需要调查的镜头成本，但不足以判断当前设备、当前代码或手机端是否流畅。现有 `tests/e2e/performance.spec.ts` 使用 `stableScene`，后者停用 CSS/SMIL 动画；其 React 样本不能代表正常动态场景的完整 FPS。

建议在新增动作及天气前，使用当前生产构建建立如下基线：

- 场景：正常动画开启的静止全景、放大房间、连续拖动、滚轮缩放、房间切换；另测首次点击详细查看的响应。
- 主题：午后、深夜和静雨优先，新增五主题后补齐；保持人物数量和资产状态可比。
- 环境：可用桌面浏览器和内置浏览器，桌面 DPR 1 / 2；手机使用真实可用设备。模拟窄屏与 CPU 降速只能作为补充，注明模拟条件。
- 指标：帧间隔分布/长帧、主线程长任务、布局/绘制/栅格化、输入到可见响应、JS/图片体积和内存。每个场景至少重复三次，保留原始结果及离散性。
- 目标：在 60Hz 设备以约 16.7ms 为帧预算参考，报告 P50/P95 和卡顿事件；不以平均值或 React render duration 代替实际帧表现。验收阈值在基线和目标设备明确后确定。

先处理测量确认的热点，候选包括大范围模糊和遮罩、持续运行的背景动态、无关 SVG 更新和首屏资源。保留用户认可的人物袍子与信箱柔和投影，以及详细查看所需的资产细节。动态优先尝试局部 transform / opacity，仍须测实际 SVG 绘制；此建议来自 [浏览器动画性能指南](https://web.dev/articles/animations-guide)，不保证带复杂滤镜的 SVG 自动进入廉价合成路径。分析方法参考 [Chrome 运行时性能文档](https://developer.chrome.com/docs/devtools/performance)。

新增方向和静态色块主要增加资产/绘制规模；真正使用多少元素、滤镜面积和同时运行的动画更重要。制作时预计算几何，只显示当前姿态；不持续重算所有方向、不让所有草簇同时逐帧变形、不为每只动物各建独立全局状态循环。需要时再按测量结果加入场景局部静态降级。

## 5. 草地：稳定的局部变化与有原因的磨损

当前地形已有渐变、少量草簇与三叶草，主屋台阶前和羊圈门口已有 `MeadowWearPatch.tsx` 断续磨损。实际全景仍有较大的均匀草色区域，可用低对比的局部变化增加材质层次，同时保留开阔留白。

建议采用三种材质角色：基础草色、偏暗湿润/密草、偏浅干草/压草。先在空旷前景做少量不规则的扁平片区，形状跟随现有地面投影，避免圆形贴纸、规则棋盘和一块块割开的草坪。位置先构图，尺寸和边缘允许受约束的随机变化，整体色差小于建筑/人物的视觉对比。

随机外观应由固定种子和稳定坐标生成，保存为静态几何或在稳定依赖中计算。人物状态、hover、天气切换和相机 pan/zoom 都不重新抽取；几何固定，主题只更换环境色。当前阶段规划已采用类似的稳定随机规则，可复用原则。

磨损围绕入口、门闩、活动落脚处安排：主屋原痕迹继续保留；可小范围试做小木屋台阶前、胶囊踏梯脚附近、常驻狗窝旁。保留草土间隔和渐淡末端，建筑入口磨损随所属建筑的位置与缩放移动，地表自然色块固定在地面空间。未来散步路线只有确实需要时才体现轻微压草，不自动形成连接所有建筑的道路。

首轮用少量静态 path 与现有渐变，无新增大范围模糊或颜色呼吸动画。色差不是太阳投影，不能直接画成永远的亮光斑；第三阶段再把草地材质与清晨/午后/黄昏/深夜/静雨的环境光统一。验收包含全景留白、近景边缘、五主题可读性、布局拖动、缩放后无闪跳、地形衔接及性能对照。

当前技术决定为**保留 React + SVG，先验证动态更新范围和静态内容复用**。少量静态家具与按需校准工具可继续小样；持续动画和大面积天气/模糊叠层会增加当前主要渲染成本，暂缓直接堆叠。Canvas/WebGL 仅作为证据支持时的局部环境层候选，未决定迁移。依据与增量成本判断见 [性能专项第 7 节](SCENE_PERFORMANCE_DIAGNOSIS.md#7-诊断后的工程决定2026-10-15)。1b 必须以明确的保留/撤回结论收尾，再回到第 2 项，不以无限测量阻塞资产制作。
