# 中远景视差连续性修复

日期：2026-10-09（Asia/Shanghai）。对应阶段 2 后出现的默认景物遮挡、山田断层、缩小后田草断层及全景漫游空旷构图。

## 原因与处理顺序

1. 默认遮挡：拖拉机与桥梁虽已进入独立视差层，原几何位置仍被更前面的麦田、草坪遮住。拖拉机从背景局部 `(75,275)` 调整到 `(75,230)`，铁路整体增加 `(0,-28)` 放置变换。它们各自保持与麦田、远山相同的刚性投影。桥脚允许自然埋入坡面，车轮与主要桥拱在默认画面可读。
2. 层间连续性：旧地形依赖固定的初始重叠。远山、麦田、草坪采用不同的纵向平移和缩放阻尼后，重叠不能覆盖整个镜头范围。新增覆盖计算延展后层已有坡面的底部曲线，避免露出山体基底、雾色平面或天空底色。
3. 漫游构图：固定 `x±420 / y[-120,300]` 边界未考虑缩放和屏幕 slice 裁切。新增建筑空间包络及可见视口计算，按 zoom 动态约束探索范围；全景上下边界保留建筑及山田层次，近景仍允许房间焦点和周边探索。
4. 回归：覆盖三个屏幕比例、四种缩放、四个平移极限、五种天气，以及有动画的反向缩放。沿真实 SVG 曲线采样检查两处接缝，另检查默认车轮和桥拱净空。

## 地形覆盖契约

入口：`src/world/scene/landscapeGeometry.ts`、`src/world/camera/parallaxMath.ts`、`src/world/render/useLandscapeCoverage.ts`。

背景局部组偏移为 `y=-115`。山麓底边的最小控制点为 238；麦田顶边最大控制点为 225、底边最小控制点为 355；草坪过渡顶边最大控制点为 190。Bézier 曲线位于控制点包络内，因此这些极值给出全宽保守覆盖。

计算前层顶边在根 SVG 中的位置，加上 8 个根 SVG 单位的重叠，再通过后层相机逆变换求需要达到的局部底边。只移动地形底部控制点，保持顶边、山脊、树林、铁路和拖拉机的刚性位置。麦田基底和纹理共用同一路径。默认 overview 的两项延展均为零。

本轮修复初始采用 700ms 镜头过渡与 750ms 覆盖收敛。后续 [房间导航优化](ROOM_NAVIGATION_OPTIMIZATION.md) 将它们统一为 400ms 与 450ms。非拖动状态保留前后目标所需延展的最大值，连续缩放重新计时；拖动时直接使用当前覆盖。效果清理计时器，静态山林与铁路通过缓存避免相机变化引起重复创建。减少动态效果的系统偏好会关闭这几层及主舞台的过渡。

修改地形控制点时，需要同步更新包络常量并运行连续性回归。地形默认覆盖域约为 x=-3200…4200，当前镜头范围内足够；未来若增加远距离世界探索，需同时扩展几何域和探索包络。

## 镜头边界契约

入口：`src/world/camera/cameraBounds.ts`、`src/world/coordinates/viewport.ts`、`src/world/scene/explorationBounds.ts`。

`visibleViewBox` 按 `xMidYMid slice` 求实际可见区域。建筑包络定义在实体局部空间，再应用 `sceneLayout` 中的位置和比例；蒸汽、气泡等动画排除在包络外，避免边界抖动。建筑可以完整放入画面时，漫游保持其在构图窗口内；放大后允许遍历建筑裁切。接近全景时逐步启用山田间距约束，zoom≥0.95 时保留当前派生房间焦点及周边平移空间。

建筑位置、房间焦点及家具局部坐标继续使用原来契约。移动建筑后探索范围会重新派生。若建筑实体几何尺寸变化，应维护其局部包络。

## 验证入口

- `npm run test:unit`：视差覆盖扫值、slice 可见区域、随 placement 与 zoom 变化的边界、各房间焦点可达性。
- `npm run test:e2e`：包含新增 11 项景观回归；在 1200×800、1600×900、390×844 三种视口分别检查 zoom 0.45 / 0.66 / 1.6 / 2.5 和四个平移角点。
- `npm run test:visual`：8 个房间视口、深夜、静雨、空席，共 11 项；有意修改的景观需要重新审阅基线。
- `npm run lint`、`npm run build`、`npm run test:preview`：类型、构建及生产入口验证。

React 开发版 Profiler 的固定拖动场景可由 `tests/e2e/performance.spec.ts` 重现。它记录 React 提交耗时，不等同于浏览器帧率或 SVG 滤镜栅格化成本。修复过程中初版覆盖状态更新产生 27 次提交、平均 42.08ms；缓存静态山林与铁路、移除拖动中的多余状态提交后，一次同场景测量为 14 次提交、平均 14.26ms、最大 23.5ms。不同运行时负载会影响数值。

最终整套回归中的重复测量为 14 次提交、平均 14.05ms、最大 17.4ms，记录于 [测量结果](metrics/LANDSCAPE-render-result.json)。这组测量针对本轮修复，不与旧 P7 的不同景观资产版本直接等同比较。

旧回归中两处测试依赖同步维护：松林节点从已移除的 `mountain-ridge-pines` 改为当前 `lowpoly-crest-pines`；校准器错误注入只针对一位小数的面板显示，避免提前破坏景观的四位小数计算。35 件家具选择/微调与 136 次把手拖动属于整组遍历，分别给出 60s / 360s 总时限，原坐标、保存、重载及相机不随家具拖动的断言继续执行。

生产预览配置同时继承开发服务器启动项，因此应在其他浏览器回归停止后独立运行。
