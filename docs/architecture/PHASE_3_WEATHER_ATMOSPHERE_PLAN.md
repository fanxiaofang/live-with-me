## 2. 已确认的体验目标

### 2.1 天空与天气

用户认为当前天空长期表现为同一类灰蓝多云天气，适合静雨，却不适合全天所有时段。第三阶段需要使五种现有主题具有清楚、舒服的差异：

| 主题入口 | 已确认的方向 | 本规划建议的具体表达 |
| --- | --- | --- |
| 清晨 `morning` | 应与普通灰蓝多云天气区分 | 清透天空、低处薄雾、浅暖地平线；保留适量云隙 |
| 午后 `afternoon` | 白天可看到太阳，偶尔出现彩虹 | 清楚的日光和局部云层；太阳露出、遮入云层；彩虹低频出现 |
| 黄昏 `dusk` | 有大片晚霞 | 大面积暖橘、粉杏与少量紫灰云层；晚霞有云形和受光层次 |
| 深夜 `night` | 能看到极光，天空应具有夜晚特征 | 深色天空、可见月亮和星空；极光作为夜景变化之一 |
| 静雨 `rainy` | 当前灰蓝、柔和、多云的感觉适合雨景 | 保留此类安静气氛，完善低云、山雾、雨丝与暖灯关系 |

太阳、晚霞和夜晚的基础配色属于主题的基本识别；彩虹和极光的出现频率、持续时间及过渡方式尚未确定。清晨具体色值、云量、光照方向也属于实现建议，不能当成已经确认的美术定稿。

### 2.2 大气、光照和观感

- 让远山、中景麦田和近处草甸形成渐进的空气透视。远景相对低对比，中景仍可辨认，主屋人物与家具保持可读性。
- 清晨和黄昏可有适度的暖光；静雨和深夜保留冷环境与暖灯的对比，避免用一层浓重色膜覆盖全部画面。
- 保持现有手绘 SVG、温暖木材和安静陪伴的风格。动态效果不抢走人物、炉火和房间活动的注意力。
- 用户已明确认可人物袍子的柔和投影，认为信箱也可以保留现状。**第三阶段不以锐利为理由统一移除软阴影。**
- 用户重视可近距离欣赏的资产细节。全景中细线自然淡化不等于资产有缺陷；不能为了全景清晰而直接删掉共用组件的细节。

## 3. 当前代码调查与问题边界

以下是当前代码事实及其影响。未确认的浏览器行为明确标为待测。

| 入口 | 代码事实 | 第三阶段应解决的问题 |
| --- | --- | --- |
| `src/world/theme/worldTheme.ts` | 有五套主题，提供天空端点、山田颜色、环境色和灯光强度 | 主题存在，但不能据此推断所有实际渲染颜色都已随主题变化 |
| `src/types.ts` / `src/App.tsx` | `TimeOfDay` 同时包含四种时段及 `rainy`，当前由用户切换 | 首轮保留入口和状态兼容，不强制改成真实天气服务或自动时间系统 |
| `src/world/render/WorldDefs.tsx` | `skyFillGrad` 的 48% 和 78% 色标分别固定为 `#96bac5`、`#dbe8e0` | 天空中段被固定浅灰蓝与浅灰绿主导，削弱深夜、黄昏的主题差异 |
| `src/components/ThreeWorld.tsx` | 天空底色矩形为 `x=-4000,y=-3000,width=10000,height=7000`；渐变默认按对象包围盒映射 | 名义 viewBox 的 y=0..800 只采到渐变约 43%..54% 区域，天空顶/底主题颜色大多位于视口之外；实际范围还受 slice 裁切影响 |
| `src/world/overlays/AtmosphereOverlay.tsx` / `ThreeWorld.tsx` | 星星和月亮位于主 SVG 之前，后者有不透明天空底色；雨层设有较高堆叠层级 | 夜空装饰存在被后绘制 SVG 遮住的路径。实施时用运行截图确认，并统一天空层级；不能只改星星亮度 |
| `src/world/render/BackgroundLandscape.tsx` | 天空几何通过空依赖 `useMemo` 固定；云和雾的几何透明度固定，引用共享渐变 | 共享渐变可更新颜色，但云量、形态和主题透明度不会自动改变；新增主题依赖必须避免过期 memo |
| `WorldDefs.tsx` / `scenery/yorkshire/landscapeTheme.tsx` | 云带、云顶、部分雾色、草地及麦田渐变仍有硬编码色标 | 需逐项区分固有材质色与环境色，避免夜景仍有白天亮草和浅蓝厚云 |
| `src/world/render/WorldDefs.tsx` | `softShadow` / `cozyShadow` 使用 `feDropShadow`；云和山雾使用 `feGaussianBlur` | 投影的模糊与物体整体模糊不同。性能优化应针对测量出的代价，不能全局禁用滤镜 |
| `src/world/camera/cameraMotion.ts` / `ThreeWorld.tsx` | 相机过渡 400ms；主舞台已去掉常驻 `will-change`，拖动时仍可提示 transform | 运动期间是否发虚、是否掉帧，仍须在实际浏览器和设备测量；拆组件、加提示均不能证明 60fps |

上表约 43%..54% 是对象包围盒渐变的代码推导，说明名义可见区域采到哪一段颜色；它不是用户设备截图的像素测量结果。

## 4. 必须保留的既有契约

1. **相机和视差**：默认全景继续为 `{x:0,y:135,zoom:0.66}`；保留 sky / mountains / wheat / stage 的平移和缩放阻尼。第三阶段可以改变天空美术，不借此调整建筑镜头或视差系数。
2. **地形连续性**：保留 `resolveLandscapeCoverage`、`useLandscapeCoverage`、地形曲线和动态裙边；当前层间至少 8 个根 SVG 单位的覆盖约束不能被雾色遮盖替代。
3. **主舞台物理坐标**：建筑、人物、家具、拖拽和房间 anchor 仍使用 1.0x 主舞台，不混入天空/天气的阻尼坐标。
4. **布局**：保留已确认的建筑间距、小木屋东南朝向与窗台花、胶囊原有正视外形、电波站后方位置，以及羊圈完整落在草台外的草甸。
5. **草地完整性**：保留短小、断续的压草和磨损；不新增连接所有建筑的连续道路，不将草地分成蛋糕状区块，不围草台添加一整圈花境。
6. **导航和交互**：保留已优化的取景和房间切换；不恢复区域虚线、选中填色和设施选中圆圈。允许底部导航遮住部分羊圈，不为避让导航移动羊圈或改全景镜头。
7. **柔和观感和细节**：人物袍子与信箱的现有投影保留；共享资产细节不能因全景尺寸小而被普遍删除。主屋清晰度和详细查看属于独立工作。
8. **业务和存储**：保留现有五种入口、RoomId、v6 布局兼容格式、人物状态和席位分配。切换天气不修改家具位置、不清空用户数据。
9. **历史验收**：原有视觉截图是历史证据。天气变化需要新截图时，应记录哪些区域有意改变，不能通过重录所有基线掩盖布局或交互回归。

## 5. 建议的实现边界

### 5.1 主题参数

保留现有 `COUNTRYSIDE_THEMES` 作为主题入口，按需要补充天空中段颜色、云亮面/暗面、云量、雾色/强度、天空装饰和环境光参数。名称与最终文件组织在实施时决定，不在规划阶段创建空模块。

- 五个入口均应有完整参数，避免用白天默认值回填深夜和静雨。
- 天空底色的安全绘制范围与渐变的可见颜色范围分别处理。建议使用绑定逻辑天空/实际可见范围的 `userSpaceOnUse` 渐变或等价方案，避免扩大底色矩形时将主题端点推离画面。
- 先明确统一的受光方向，再调整山脊亮边、云底、麦田受光和环境阴影；不能给每个资产添加互不一致的光源。
- 各主题可以改变环境对比和受光，仍保留木材、陶瓦、植物和草地的材质辨识。

### 5.2 天空与天气绘制层级

推荐逻辑顺序为：天空底色 → 星/月/太阳/极光/彩虹等天空现象 → 云层 → 远山及分层雾 → 麦田 → 主舞台 → 必要的雨丝前景。

最终实现仍需依照各现象的遮挡关系安排局部位置，例如太阳可被云遮住、极光在云后、彩虹在远山背景。雨丝前景单独处理，不将所有天气装饰放到人物和建筑之上。

- 大范围安全底色可固定覆盖视口；天空装饰与云层沿用 sky 层的景深关系，远山雾按所属地形层投影。
- 天空元素在房间放大时可移出视口，不要求强行悬浮在每个房间上方。
- 所有装饰层不拦截点击、拖动、触摸或键盘焦点。
- 原有月亮、星星应迁移或复用，消除重复实例及层级遮挡。
- 若未来多处 SVG 预览同时渲染，渐变、遮罩及滤镜 ID 必须隔离，防止互相引用错资源。

### 5.3 偶发天空现象

- 彩虹是白天的低频变化；建议表达为雨后云隙与日光条件，保持轻、淡、有弧度。首轮可在现有午后主题中建立内部“雨后”变化，不必新增导航入口。
- 极光是夜景变化。建议让普通星夜仍有完整画面，极光缓慢出现和消退，不长期铺满高饱和荧光带。
- 太阳、晚霞、月亮和星空提供基础识别，不能依赖等待随机事件才能知道当前主题。
- 进入主题、拖动镜头或 React 重渲染不能反复抽取随机外观。需要稳定的场景状态/种子；频率、冷却和时长在首个静态样例通过后再确定。
- 测试应能强制普通夜景、极光夜景、普通日景和彩虹日景等状态，避免截图和验收依赖随机等待。
- 暂不添加真实天气 API、地理定位、自动日历时钟、新音效或通知。

### 5.4 大气与环境动态

清晨雾薄且偏低，黄昏雾带暖色反射，静雨层次偏冷，深夜远山维持低亮度轮廓。雾层只能增强已有的真实地形关系，不能遮住空隙来通过连续性验收。

山谷流岚可以有两层很慢的交错位移与轻微透明度变化；先验证静态层次，再加入动画。保留麦浪、列车、烟雾等已有动态，新增动态必须控制总密度。

雁阵、列车蒸汽节奏或其它生态叙事是原始评估中的建议，**本轮尚未确认实施**。如后续采用，宜作为独立可选批次，不能让热气球、风车、新设施等占据天空或改变现有布局。

### 5.5 性能处理

- 先测生产构建下的静止、主题切换、房间切换、连续 pan、wheel 和双指缩放，分别记录 React 提交与浏览器绘制/帧间隔。
- 首选减少背景大滤镜面积、重复模糊层、无收益的常驻合成提示，以及主题切换时的大范围无关提交。
- `React.memo` 和静态几何复用可以保留，但主题变化必须能更新对应参数；不能以空依赖 memo 冻结主题外观。
- 若测量仍显示背景模糊为主要瓶颈，再试交互期间降低背景雾/云滤镜成本；需要覆盖拖动、wheel、pinch、房间过渡，不仅检查 `isDragging`。
- 降级保留几何、覆盖和整体色调，恢复质量时不能跳色、露接缝或突然变亮。人物投影和主屋细节不作为首批降级对象。
- 支持 `prefers-reduced-motion`，对云、极光、雾、闪烁和新增现象提供稳定静态或轻淡切换；不要让普通星星频繁闪烁。
- 性能目标在基线测量后设定。60Hz 设备的 16.7ms 帧预算可作参考，不能在没有完整浏览器测量时宣称所有设备 60fps。

| T3-6 完整交付 | 回归镜头、地形、交互、存储、预览和减少动态效果；核对用户视觉验收 | 代码、验收截图、性能记录及本规划状态一致，可独立回退 |

性能观察贯穿所有批次，不等到最后才发现过多滤镜。T3-5 是集中复测及微调，并非首次性能检查。

可选生态动态另行排期。不得因原始评估提到它们，自动纳入 T3-4 或无限扩大第三阶段范围。

## 7. 验收与复验方法

### 7.1 视觉和交互

- 五种基础主题均检查全景、主屋典型房间和天空可见的平移位置；夜景的星/月可见，黄昏出现大面积晚霞，白天有日光识别，静雨维持安静灰蓝气氛。
- 彩虹和极光分别检查不出现、出现、渐入/渐出、切换主题、切换房间和快速反复切换。装饰不截获场景操作。
- 检查主屋木材、人物肤色、袍子、信箱、挂画及书架细节；天气不能造成持续发虚、过曝或一整块发黑。
- 回归小木屋、胶囊、电波站和羊圈的坐标、点击区、人物槽位、家具校准及刷新保存。
- 如书架/柜子详细预览已实现，检查其当前陈设与主屋一致，天气资源不串用 SVG ID，不因装饰层出现而失去交互。

### 7.2 地形和镜头矩阵

以现有 `tests/e2e/landscape.spec.ts` 和 `tests/unit/parallax.test.ts` 为回归入口：

- 视口至少包含 1200×800、1600×900、390×844、1920×800。
- zoom 至少覆盖 0.45、0.66、1.6、2.5，四个平移极限以及连续反向缩放。
- 五种主题都检查山体/麦田、麦田/草地两处接缝；在关闭装饰雾层的诊断对比中也没有断层。
- 默认相机不变，拖拉机车轮与高架桥桥拱可见，羊圈可通过现有镜头范围查看。
- 保留 `room-navigation.spec.ts`、`sheep-pen.spec.ts`、输入/布局回归。底部导航遮挡不作为羊圈位置失败条件。

### 7.3 性能与截图

- 明确记录开发/生产、浏览器版本、视口、DPR、硬件、主题、动画状态和测试操作；对照使用相同环境。
- 至少对可用环境测 DPR=1 和 DPR=2 下的静止清晰度与镜头运动；内置浏览器的视觉结论需要单独复核，不能用无头 Chromium 完全替代。
- 性能采样不暂停动画；固定截图才暂停或设置确定性动画时刻。测量重复采样并记录离散性，不以单次最好值代表常态。
- 全屏录制/trace 自身可能改变重型 SVG 的测量开销，出现这种情况需记录并使用同样操作的轻量复验。
- 保留历史基线。新主题截图作为有意视觉变化的独立证据，注明更新原因和保护区域，不批量覆盖旧图。
- 类型、单元、浏览器和构建均通过后，再根据剩余问题决定是否增加检查；历史通过次数不当作新批次已通过。

候选命令（实施时按改动范围运行，本次规划没有执行这些回归）：

```text
npm run lint
npm run test:unit
npx playwright test tests/e2e/landscape.spec.ts tests/e2e/room-navigation.spec.ts tests/e2e/sheep-pen.spec.ts --trace=off
npm run test:e2e
npm run test:visual
npm run build
npm run test:preview
```

新增测试集中于主题参数、天空/地形遮挡、稳定现象状态、交互和回归约束，不为每条装饰路径编写镜像测试。
