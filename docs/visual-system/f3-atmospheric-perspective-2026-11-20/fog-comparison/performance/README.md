# C+ 实时体积雾 / 光学缓存：定向性能测量（2026-11-21）

测量入口：http://localhost:3000/tests/fixtures/fog-performance.html 。正常应用不启动此探针；诊断模块按需动态加载。

本轮按用户提出的性能比较请求，只测两个雾层，不重启整页性能专项、不做全量测试/跨浏览器矩阵。复用了现有独立诊断与原始证据保留方式；既有 diagnose-scene-performance.mjs 是整页生产预览工具，不用于此局部问题。

## 环境与方法

Windows / Chrome 157 / ANGLE Direct3D11 / Intel UHD Graphics（0x00009BCA）。固定 1600×900 CSS，DPR 1.5，绘制缓冲 2400×1350。直接复用项目 C+ 与烘焙实现、同一 renderer/投影/布局；未渲染 SVG 前景和其他整页层。Vite 开发诊断入口，非整页生产版本测量。

着色器预热后，每版 16 次计时，按实时/缓存/实时/缓存分段交替；两轮结果一致。使用 EXT_disjoint_timer_query_webgl2 获取 GPU 纳秒计时并换算毫秒，第二轮无 disjoint 丢弃样本。另做一次显式失效后的预热重烘焙，计入离屏烘焙和一次屏幕合成。

CPU 提交耗时包含 gl.finish 调用，但浏览器命令缓冲意味着 JS 墙钟耗时不能证明 GPU 已完成；GPU 成本以 timer query 为依据。首轮原始字段名 synchronized 容易误解，已在第二轮改为 submission；保留首轮原始证据，最终报告采用 run-02.json。

## 第二轮结果

| 指标 | 实时 C+ | 烘焙缓存 |
| --- | ---: | ---: |
| 雾层单次 GPU 中位耗时 | 42.178 ms | 1.008 ms |
| 雾层单次 GPU P95 | 45.290 ms | 1.100 ms |
| CPU 提交中位耗时 | 0.700 ms | 0.700 ms |

GPU 单次绘制成本约相差 41.84 倍，减少 97.61%。这是雾层自身的差别，不是应用整体 FPS 提升倍数。

预热后的显式重烘焙 GPU 352.777 ms（一次样本，包含一次合成）；该次 CPU 提交约 2.6 ms。首次页面进入还涉及材质/着色器编译、驱动缓存、初始化，不能以该数字替代首次加载延迟。前一轮交付时约 3 秒的 bakeSubmitMs 是含编译的 CPU 提交记录，不是 GPU 测量。

缓存 2160×280 RGBA16F，纹理本体约 4.61 MiB，未计驱动/程序/其他资源。正常相机交互复用一次烘焙，第二轮 bakeCount=2 是诊断主动失效重烘焙造成，非相机移动触发。

静止时两方案本就停止绘制，持续渲染开销均近零；主要收益在镜头交互/其他重绘。当前刷新会重建 GPU 缓存。长期纹理导出/预热不属于本次测量。

原始记录 run-01.json / run-02.json；汇总与源码哈希 summary.json；页面截图 results.png。当前机器为核显，独显/手机及不同面积、DPR、雾体积配置的结果会不同。未测整页 FPS、输入延迟、功耗或温度。
