## 建议落地顺序

1. 按清单提交已批准的木屋实现、必需新组件、默认配置、取景/交互测试与最终说明，排除未批准或无关的工作区资料。
2. 修正已删除树根节点的测试契约，重跑七项浏览器回归，确保首页、窄屏、默认一致性、加载回退和键鼠访问确实完成验证。
3. 整理主线文档/证据范围；不为合并清理而删除用户本地历史资料。
4. 以已核对 main 为基线形成干净的集成分支/PR，优先考虑整理后的 squash 合并；完整试验历史仍保留在 F2 分支。若希望完整保留 51 个试验提交和全部产物，快进也可行，但主线体量和历史会更重。
5. 合并前再次核对远端 main。上述步骤通过后再实际合并。

历史近景田间物件遮挡、真实移动硬件和 Safari/Firefox 性能验证仍是已记录的后续边界，不以这次 Edge 回归替代全设备验收。
